# 考場筆記｜Personal IELTS Desk

> 一個以弱點為中心的個人雅思學習平台：把查過的單字、答錯的題目、寫作回饋與讀書計畫串成可持續執行的複習系統。

[線上體驗](https://ielts-study-desk.pages.dev)

## 專案介紹

準備 IELTS 時，真正困難的不只是找到題目，而是把每天的學習資料轉換成下一步該複習什麼、該加強哪一種題型。考場筆記將單字記憶、模擬練習、錯題紀錄與學習排程整合到同一個工作流，協助使用者用自己的資料安排複習與練習。

這是一個以繁體中文介面設計的個人學習工具，重點在於降低記錄成本、讓 AI 回饋可以被保留與再利用，並兼顧本機資料掌控與跨裝置使用情境。

## 功能一覽

| 模組 | 說明 |
| --- | --- |
| 個人電子單字庫 | 輸入英文單字後，由 AI 協助整理字義、用法等資料；確認後加入單字庫與複習佇列。 |
| 今日複習 | 採用 Leitner 五盒間隔重複系統；答對升盒、答錯回到第一盒，並提供英翻中與中拼英模式。 |
| 擬真考題 | 依單字庫與錯誤紀錄產生閱讀、寫作、聽力、口說與單字應用練習；聽力題可使用瀏覽器語音朗讀。 |
| 錯誤筆記本 | 集中記錄各技能與子題型的失誤，視覺化弱點分布，供後續診斷與出題使用。 |
| 寫作批改 | 依 IELTS Writing Band Descriptors 的四項標準提供評分、回饋與範文。 |
| 每日讀書計畫 | 可手動建立每日任務，也可依考試日期、目前／目標分數、可讀書時數與弱點生成計畫。 |
| 備份與跨裝置進度 | 支援 JSON 匯出／還原；可選擇註冊帳號，將加密驗證後的進度儲存到雲端。 |

## 使用流程

1. 在「設定」頁輸入自己的 Gemini API Key，選擇可用模型與發音口音。
2. 到「單字庫」查詢並儲存新單字，系統會自動納入複習排程。
3. 每日完成待複習單字，透過五盒機制累積長期記憶。
4. 使用「擬真考題」與「寫作批改」練習；將錯誤回寫到錯誤筆記本。
5. 根據弱點分析調整讀書計畫，並定期匯出備份或同步雲端資料。

## 技術與架構

- **前端**：單一 HTML 檔（`ielts.html`），無框架、無打包步驟，全部邏輯內嵌
- **部署**：Cloudflare Pages
- **後端（選用）**：Cloudflare Pages Functions + D1，提供帳號與跨裝置進度儲存
  - 帳號以「使用者名稱 + 密語」登入，密語經 PBKDF2 雜湊後才存
  - 存取權以簽章 token 驗證
  - 以樂觀鎖（optimistic locking）防止多裝置互相覆蓋
- **AI**：Google Gemini API，由使用者在瀏覽器端提供個人 API Key
- **本機資料**：瀏覽器 `localStorage`，支援 JSON 備份與還原
- **語音**：Web Speech API，提供英式／美式發音與聽力練習

### 資料設計原則

- **本機優先**：核心學習資料先保留在使用者目前瀏覽器，降低開始使用的門檻。
- **雲端選用**：需要跨裝置時才建立帳號與同步，單一裝置使用者仍可透過 JSON 備份掌握資料。
- **不儲存 API Key**：Gemini Key 僅存於使用者自己的瀏覽器 `localStorage`，並由瀏覽器直接呼叫 Gemini API。
- **避免靜默覆寫**：同時在多台裝置修改時，較舊的上傳會被阻擋並提示先下載最新資料。

## 本機開發

前端是單一 HTML 檔，直接用瀏覽器開 `ielts.html` 就能操作大部分功能（不需要 build）。

需要動到後端或部署時：

```bash
# 安裝依賴
npm install

# 建立本機環境變數（Pages Functions / D1 用）
cp .dev.vars.example .dev.vars

# 跑測試
npm test

# 建置並部署到 Cloudflare Pages
npm run deploy
```

部署細節見 `DEPLOY-backend.md`。

### 必要設定

| 設定 | 用途 |
| --- | --- |
| Gemini API Key | 啟用單字整理、模擬題、弱點診斷、寫作批改與智慧讀書計畫。使用者可在網站的「設定」頁自行輸入，不需寫進程式碼。 |
| D1 binding | 啟用選用的跨裝置進度與帳號功能。 |
| `TOKEN_SECRET` | 簽發與驗證登入 token。以 Cloudflare 環境變數設定，**不進版控**。 |

## 安全性提醒

- 部署到正式網域後，應在 Google Cloud Console 為 Gemini API Key 設定 **HTTP referrer 限制**，只允許自己的網站網域。
- API Key 與 `TOKEN_SECRET` 不應寫入 Git、前端程式碼或公開環境變數。
- `localStorage` 可能因清除瀏覽資料、換裝置，或 iOS Safari 長時間未使用而遺失；建議使用者每週匯出備份。

## 已知問題

- **手機版導覽列**：在約 375px 寬的螢幕上，側邊欄會擠成頂部長條且中文字直排，佔用過多垂直空間並產生橫向捲軸。`@media (max-width:800px)` 這段需要重寫。
- 沒有 Open Graph 標籤，分享連結時不會顯示預覽卡片。

## 未來優化方向

1. **作品集首頁與 Demo 資料**：目前新使用者看到的是空狀態與 API Key 提示。提供「試用範例資料」或 60 秒導覽，可讓訪客不設定 Key 也能理解完整閉環。
2. **隱私與信任頁面**：新增 Privacy Policy、資料流向圖與 API Key 安全說明。這會讓使用者更願意輸入自己的 Key 與建立跨裝置帳號。
3. **後端測試**：前端已有測試（`npm test`），但 Pages Functions 的帳號、token 與同步衝突邏輯尚無自動化測試，是目前最該補的一塊。
4. **可近用性與行動裝置**：除了上述導覽列問題，還需測試鍵盤操作、focus 狀態、色彩對比與小螢幕版的練習流程，尤其是聽力播放與作文輸入區。
5. **可量化成效**：在儀表板新增「本週完成率、弱點趨勢、預估複習量」等指標。
6. **可觀測性**：以不記錄學習內容與 API Key 為前提，蒐集匿名錯誤事件、AI 請求失敗率與同步衝突率，方便發現正式環境問題。
